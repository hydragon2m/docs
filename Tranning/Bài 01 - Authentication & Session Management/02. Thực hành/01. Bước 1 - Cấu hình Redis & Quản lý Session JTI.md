## I. MỤC TIÊU CỦA BƯỚC NÀY
Trong bước này, chúng ta sẽ hiểu và cài đặt tầng lưu trữ **Redis** để quản lý mã định danh **`jti` (JWT ID)** cho từng phiên đăng nhập của người dùng.

---

## II. HÌNH DUNG ĐƠN GIẢN VỀ `jti` VÀ REDIS

* **`jti` là gì?** Hãy tưởng tượng `jti` giống như **mã vạch của một tấm vé**. Mỗi lần người dùng đăng nhập hoặc đổi vé mới, một mã vạch ngẫu nhiên duy nhất (UUID v4) sẽ được in lên vé.
* **Redis làm nhiệm vụ gì?** Redis đóng vai trò như **cuốn sổ ghi chép siêu tốc trên RAM**. Nó ghi lại: *"Tài khoản Alex trên máy tính Chrome hiện đang giữ tấm vé có mã vạch là `abc-123`"*.
* **Tại sao không lưu trong Database thông thường (MySQL/PostgreSQL)?** Vì Redis lưu trên RAM, tốc độ đọc/ghi đạt dưới 0.2 mili-giây và hỗ trợ cơ chế tự động xóa vé hết hạn (TTL), không làm nặng Database chính.

---

## III. CẤU TRÚC DỮ LIỆU LƯU TRONG REDIS

Chúng ta sử dụng cấu trúc Key-Value dạng chuỗi với quy ước đặt tên:
* **Tên Key:** `session:<userId>:<deviceId>`
* **Giá trị Value:** Chuỗi `jti` hợp lệ hiện tại (ví dụ: `d3b07384-d113-4944-9343-4f9fa5d69112`)
* **Thời gian sống (TTL):** Đúng bằng thời hạn của Refresh Token (7 ngày = `604800` giây). Sau 7 ngày, Redis tự xóa key này khỏi RAM.

```text
VÍ DỤ TRONG RAM REDIS:
session:usr_998877:chrome_windows  ==>  "3fa85f64-5717-4562-b3fc-2c963f66afa6" (TTL: 7 ngày)
session:usr_998877:iphone_safari   ==>  "e6a47a76-2e71-4a5f-9204-58a2d3b4e999" (TTL: 7 ngày)
```

## IV. BƯỚC LÀM CỤ THỂ TRONG CODE BACKEND (NESTJS)

Mở file: [`src/redis/redis.service.ts`](file:///home/hy/Documents/Obsidian%20Vault/Tranning/B%C3%A0i%2001%20-%20Authentication%20&%20Session%20Management/02.%20Th%E1%BB%B1c%20h%C3%A0nh/backend-nestjs/src/redis/redis.service.ts)

Chúng ta cần viết 4 hàm thao tác cốt lõi:

### 1. Hàm lưu phiên khi Đăng nhập hoặc Refresh (`setSession`)
```typescript
async setSession(userId: string, deviceId: string, jti: string, ttlSeconds: number): Promise<void> {
  const key = `session:${userId}:${deviceId}`;
  // Lệnh 'SET key value EX ttl' lưu giá trị và tự hủy sau ttlSeconds
  await this.client.set(key, jti, 'EX', ttlSeconds);
}
```

### 2. Hàm đọc mã `jti` để kiểm tra phiên có hợp lệ không (`getSession`)
```typescript
async getSession(userId: string, deviceId: string): Promise<string | null> {
  const key = `session:${userId}:${deviceId}`;
  // Trả về chuỗi jti nếu còn hạn, hoặc null nếu đã logout/hết hạn
  return await this.client.get(key);
}
```

### 3. Hàm xóa 1 phiên khi người dùng bấm Đăng xuất (`deleteSession`)
```typescript
async deleteSession(userId: string, deviceId: string): Promise<void> {
  const key = `session:${userId}:${deviceId}`;
  await this.client.del(key);
}
```

### 4. Hàm xóa toàn bộ phiên trên mọi thiết bị khi đổi mật khẩu (`deleteAllSessions`)
```typescript
async deleteAllSessions(userId: string): Promise<number> {
  const pattern = `session:${userId}:*`;
  let cursor = '0';
  let deletedCount = 0;

  // Dùng lệnh SCAN thay vì KEYS để không làm nghẽn CPU của Redis
  do {
    const [nextCursor, keys] = await this.client.scan(cursor, 'MATCH', pattern, 'COUNT', 100);
    cursor = nextCursor;

    if (keys.length > 0) {
      await this.client.del(...keys);
      deletedCount += keys.length;
    }
  } while (cursor !== '0');

  return deletedCount;
}
```

## V. KIỂM CHỨNG BƯỚC NÀY
Khi bạn chạy Docker Redis:
```bash
docker run -d --name redis-lab -p 6379:6379 redis:alpine
```
Bạn có thể mở terminal gõ `docker exec -it redis-lab redis-cli` rồi gõ `KEYS session:*` để tận mắt thấy các key phiên được tạo ra và quản lý.
